# Notes App

Приложение заметок на `React + TypeScript`, собранное как продуктовый интерфейс, а не как демо-шаблон. Внутри есть блоки заметок, группировка записей по датам, редактор с автосохранением, настройки интерфейса и полная интеграция `MUI + React Hook Form + Zod + Zustand`.

## Стек

- `React 19` + `TypeScript`
- `Vite`
- `Material UI` + `@mui/x-date-pickers`
- `React Router v6`
- `React Hook Form`
- `Zod` + `@hookform/resolvers`
- `Zustand` + `persist`
- `ESLint` + `Prettier`

## Как запустить

```bash
npm install
npm run dev
```

Дополнительно:

```bash
npm run lint
npm run build
```

## Что и зачем сделано

- Главная страница показывает сетку блоков, потому что это основной рабочий сценарий: быстро увидеть контекст, последнее содержимое и дату активности.
- Карточка блока показывает не только название, но и превью последней заметки, число заметок и метку категории, чтобы пользователь мог выбрать нужный блок без лишних переходов.
- Фильтры через `MUI Tabs` позволяют моментально отделить обычные блоки от блока без категории.
- Создание блоков и заметок реализовано через `React Hook Form` с `Controller`, потому что все поля построены на MUI-компонентах и должны корректно работать с валидацией и состоянием формы.
- `Zod` описывает реальные ограничения интерфейса: минимальная длина названия, максимум символов, обязательные подтверждения.
- Страница блока группирует заметки по дате под липкими заголовками, чтобы лента читалась как хронология, а не как плоский список.
- Редактор заметки сохраняет изменения по `blur` и через debounce `500ms`, что соответствует реальному текстовому приложению и снижает риск потерять текст.
- Настройки влияют на интерфейс по-настоящему: тёмная тема переключает глобальную тему, размер шрифта применяется через MUI theme, автосохранение используется редактором, а вид заметок и каналы уведомлений сохраняются в store.
- `Zustand persist` сохраняет блоки, заметки и настройки в `localStorage`, поэтому состояние восстанавливается после перезагрузки.
- `vite-plugin-eslint` подключён в `vite.config.ts`, чтобы ошибки линтера были видны во время HMR.

## Конфигурация качества

- Ручной `.eslintrc.cjs` настроен без дефолтного vite-конфига.
- `.prettierrc` соответствует заданным правилам форматирования.
- Все формы и store типизированы, `any` не используется.

## Примечание по дизайну

Скриншоты в рабочем каталоге не были приложены к текущей сессии, поэтому визуальный стиль собран по вашему описанию: насыщенный янтарный акцент, тёмные карточки, крупная типографика, плавающие FAB-кнопки и mobile-first раскладка.
