# Workout Tracker

Фитнес-приложение на `React + TypeScript` с акцентом на три рабочих сценария: планирование программ, календарь выполнения и аналитика прогресса. Интерфейс собран как продуктовый трекер тренировок на `MUI`, а все формы работают через `React Hook Form + Controller`.

## Стек

- `React 19` + `TypeScript`
- `Vite`
- `Material UI` + `@mui/x-date-pickers`
- `React Router v6`
- `React Hook Form`
- `Zod` + `@hookform/resolvers`
- `Zustand` + `persist`
- `ESLint` + `Prettier`

## Запуск

```bash
npm install
npm run dev
```

## Что реализовано

- Дашборд на главной показывает недельную статистику, общий тоннаж, лучший PR, текущий стрик, сравнение недель, мышечную карту и прогрессию по жиму лёжа.
- Планирование тренировок вынесено в отдельный экран: можно создавать программы на недели вперёд, задавать тренировочные дни и прикреплять к каждому дню упражнения из библиотеки.
- Библиотека упражнений хранит реальные шаблоны: название, группа мышц, тип оборудования и рабочую схему `подходы × повторения × вес + отдых`.
- Календарь показывает расписание и историю: зелёные дни означают выполненные тренировки, серые — пропуски, янтарные — запланированные сессии.
- Детальная страница программы показывает структуру недели и преднастроенные схемы по каждому упражнению.
- Аналитика считает тоннаж, прибавку по рабочему весу, оценочный `1RM`, личные рекорды и сравнение текущей недели с прошлой.
- Настройки сохраняются в `localStorage`, включая тему, размер шрифта, уведомления и пользовательские предпочтения.

## Почему компоненты и формы выглядят осмысленно

- `CreateProgramDrawer` использует `React Hook Form`, потому что создание программы требует связанной структуры данных: цель, длительность, дни недели, группы мышц и выбранные упражнения.
- `CreateExerciseDialog` нужен не ради демо-поля, а для поддержки библиотеки шаблонов, от которой зависят планировщик и аналитика.
- Карточки программ, статкарточки и календарные ячейки показывают не абстрактный UI, а конкретные метрики пользователя: расписание, объём, PR и статус выполнения.
- `Zustand persist` выбран потому, что приложение по смыслу должно восстанавливать историю и планы после перезагрузки без сервера.
- `vite-plugin-eslint` включён в `vite.config.ts`, чтобы проблемы были видны сразу в режиме разработки.

## Ограничение текущей версии

Отдельный экран активной тренировки не реализован намеренно: по текущему ТЗ приложение покрывает только планирование, календарь и аналитический слой без live-flow во время сессии.
